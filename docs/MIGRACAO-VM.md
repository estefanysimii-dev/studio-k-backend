# Backend Studio K em Linux

Pacote portavel para uma maquina Linux ja disponivel, com Docker Engine, Compose v2 e Node 24.17+ para os scripts locais. **Nenhuma hospedagem foi contratada ou escolhida; nenhum bot foi iniciado. Ainda falta recuperar o backup de producao do Railway.** O portifolio permanece no InfinityFree. Um host gratuito precisa permitir processo continuo, disco persistente, saida HTTPS/WebSocket e UDP de voz; Workers Free nao executa diretamente o SQLite local e o conversor Rust atuais.

1. **Recupere os dados antes do corte.** Com todos os escritores parados, exporte o diretorio original inteiro (banco, WAL/SHM existentes, `encryption.key`, uploads, backups e configuracoes):
   ```sh
   node app/deploy/backup-offline.mjs /caminho/data /backup/studio-k.tar.gz --offline-confirmed
   ```
   O comando copia e verifica sem alterar a origem, inclui manifesto e gera SHA-256. A chave tem 32 bytes e precisa corresponder ao banco; so codigo ou backup JSON nao basta. Copias temporarias privadas ficam preservadas para inspecao. Nao use `.incomplete`. O parametro confirma que voce ja parou os escritores; nao os para automaticamente.
2. **Restaure em destino novo.** Use `/srv/studio-k/app` para este repositorio e `/srv/studio-k/data` para os dados. Verifique `sha256sum -c studio-k.tar.gz.sha256`, inspecione `tar -tzf studio-k.tar.gz` e extraia somente seu backup confiavel, em pasta vazia com `umask 077`; copie a pasta `data` para o destino ainda inexistente. Nao sobrescreva uma instalacao. Execute `node app/deploy/verify-data.mjs data` de `/srv/studio-k`. Ele exige banco configurado e chave, verifica integridade e relacionamentos em uma copia e, havendo valores cifrados, autentica amostras sem imprimir segredos. Nao importa `server/store.js` nem cria um banco novo.
3. **Configure antes de publicar.** Copie `app/deploy/runtime.env.example` para `/srv/studio-k/.env` (fora do Git) e aplique `chmod 600 .env` e `chmod 700 data`. Preserve credenciais e a chave original. Prepare o novo dominio HTTPS e DNS; Caddy precisa receber 80/443, enquanto a API 8080 fica apenas na rede Docker. Configure `STUDIO_DOMAIN`, `PUBLIC_URL` e `PORTFOLIO_BACKEND_URL` com o novo backend; mantenha `PORTFOLIO_PUBLIC_URL=https://studiokatelier.infinityfreeapp.com`. Troque o endereco privado da traducao por um servico acessivel antes de ativar esse recurso. Nao use dados de demonstracao.
4. **Prepare o OAuth e o corte.** Adicione no Discord `https://NOVO_BACKEND/api/oauth/discord/callback` e no Google `https://NOVO_BACKEND/api/oauth/google/callback`, mantendo os callbacks antigos durante a validacao. Depois atualize o backend URL no adaptador PHP do InfinityFree. O novo dominio do painel exige novo login porque cookies pertencem ao dominio antigo; preservar o banco/chave evita apagar sessoes e autorizacoes persistidas. Nao rotacione credenciais, limpe sessoes ou remova callbacks antes dos testes. Para ensaiar, use copia isolada e sem token do bot; nunca conecte dois bots com o mesmo token. Este Compose e para o corte de producao, nao para esse ensaio.
5. **Valide e suba somente apos restaurar.** De `/srv/studio-k`:
   ```sh
   docker compose --project-directory . --env-file .env -f app/deploy/compose.yaml config --quiet
   docker compose --project-directory . --env-file .env -f app/deploy/compose.yaml build backend
   # Corte: origem parada; backup final restaurado e verificado; DNS/OAuth preparados.
   docker compose --project-directory . --env-file .env -f app/deploy/compose.yaml up -d
   ```
   A partida e cada reinicio verificam os dados antes de executar o servidor; uma pasta inexistente nao e criada pelo bind. Confirme `/healthz`, login Discord/Google, Central Staff, uploads/preview FiveM, tickets, estoque/entrega e pagamentos em sandbox antes de encerrar a origem. O backend tenta reiniciar no maximo tres vezes apos falha; apos corrigir o problema ou reiniciar o host, execute `up -d` novamente. Copias privadas da verificacao ficam em `/tmp/studio-k-preflight-*`; acompanhe o espaco livre. Para outro backup offline, pare `backend` no Compose e so o religue apos terminar. Nao ha remocao de dados, reinicio do host, instalacao de pacotes ou deploy automatico nestes scripts. Este pacote foi verificado localmente, mas requer validacao Docker/HTTPS no host real.
